# PyThermoDB-Settings v0.9.0 Release

## Overview

v0.9.0 extends the **Component modeling system** with comprehensive helper
methods for inspecting chemical species. This release focuses on convenient
species classification, charge-center analysis, radical detection, physical
state checks, formula annotation handling, and component identity generation.

## ✨ New Features

### 1. **Species Classification Helpers**

The `Component` model now provides predicates for querying automatically
derived species classifications:

```python
component.has_species_type("cation")
component.is_neutral()
component.is_cation()
component.is_anion()
component.is_radical()
component.is_zwitterion()
component.is_ionic()
```

Components can have multiple classifications, such as an anion that is also a
radical. Zwitterions are identified separately when positive and negative
charge centers balance to a net charge of zero.

### 2. **Charge-Center Helpers**

The model now exposes both net charge and the local charge centers encoded in a
formula:

```python
component.get_charge_centers()
component.get_net_charge()
component.has_charge_centers()
component.has_internal_charges()
component.get_charge_center_count()
component.get_positive_charge_count()
component.get_negative_charge_count()
component.get_total_positive_charge()
component.get_total_negative_charge()
component.is_charged()
```

**Examples:**

- `Fe{3+}` -> charge centers `[3]`, net charge `3`
- `NH3{+}-CH2-COO{-}` -> charge centers `[1, -1]`, net charge `0`
- `O2{*2-}` -> charge centers `[-2]`, net charge `-2`

These methods distinguish a neutral net charge from the presence of internal
positive and negative charge centers, which is useful for zwitterions.

### 3. **Radical Helpers**

Radical annotations can be inspected independently of the component's net
charge:

```python
component.get_radical_count()
component.has_radical_centers()
component.is_radical_ion()
```

The peroxide radical dianion formula `O2{*2-}` is automatically recognized as
both an anion and a radical, and `is_radical_ion()` returns `True`.

### 4. **Physical State Helpers**

Phase-specific checks are now available for all supported component states:

```python
component.is_gas()
component.is_liquid()
component.is_solid()
component.is_aqueous()
```

Supported states are still:

- `"g"` - Gas
- `"l"` - Liquid
- `"s"` - Solid
- `"aq"` - Aqueous solution

### 5. **Formula Helpers**

The model can return the base formula without charge or radical annotations
and can report whether annotations are present:

```python
component.get_base_formula()
component.has_annotations()
```

For example, `O2{*2-}` returns `O2` from `get_base_formula()` and `True` from
`has_annotations()`.

### 6. **Identity and Key Helpers**

New identity methods provide consistent identifiers for indexing, comparison,
and mixture assembly:

```python
component.get_name_state()
component.get_formula_state()
component.get_name_formula()
component.get_name_formula_state()
component.get_formula_name_state()
component.get_key("Name-State")
component.get_identity()
```

Supported key formats include:

- `Name-State`
- `Formula-State`
- `Name-Formula`
- `Name`
- `Formula`
- `Name-Formula-State`
- `Formula-Name-State`

`get_identity()` returns a `ComponentIdentity` model containing the
name-state, formula-state, and name-formula identifiers.

## 📋 Supported Component Examples

The v0.9.0 examples demonstrate the new helper methods across four chemical
species categories:

### Neutral Molecules

- Carbon dioxide: `CO2` in the gas phase
- Net charge: `0`
- Species type: `neutral`

### Cations

- Iron(III): `Fe{3+}` in the solid phase
- Net charge: `3`
- Species type: `cation`

### Zwitterions

- Glycine zwitterion: `NH3{+}-CH2-COO{-}` in the solid phase
- Charge centers: `[1, -1]`
- Net charge: `0`
- Species type: `zwitterion`

### Radical Anions

- Peroxide radical dianion: `O2{*2-}` in the aqueous phase
- Net charge: `-2`
- Species types: `anion`, `radical`

## 🔍 API Examples

### Neutral Component

```python
from pythermodb_settings.models import Component

carbon_dioxide = Component(
    name="Carbon dioxide",
    formula="CO2",
    state="g",
)
print(carbon_dioxide.is_neutral())  # -> True
print(carbon_dioxide.is_gas())      # -> True
print(carbon_dioxide.get_net_charge())  # -> 0
```

### Charged Component

```python
iron_iii = Component(
    name="Iron(III)",
    formula="Fe{3+}",
    state="s",
)
print(iron_iii.get_charge_centers())        # -> [3]
print(iron_iii.get_total_positive_charge()) # -> 3
print(iron_iii.is_cation())                 # -> True
```

### Zwitterion

```python
glycine = Component(
    name="Glycine zwitterion",
    formula="NH3{+}-CH2-COO{-}",
    state="s",
)
print(glycine.get_charge_centers())   # -> [1, -1]
print(glycine.has_internal_charges()) # -> True
print(glycine.is_zwitterion())         # -> True
```

### Radical Ion

```python
peroxide = Component(
    name="Peroxide radical dianion",
    formula="O2{*2-}",
    state="aq",
)
print(peroxide.get_radical_count()) # -> 1
print(peroxide.get_base_formula())  # -> "O2"
print(peroxide.is_radical_ion())    # -> True
```

## 📦 Component Model Structure

```python
class Component:
    name: str                    # Component name
    formula: str                 # Chemical formula with charge/radical notation
    state: str                   # Physical state: "l", "g", "s", "aq"
    charge: int                  # Electric charge (inferred or provided)
    species_type: List[str]      # Classification: neutral, cation, anion, radical, zwitterion

    # Species helpers
    is_neutral()
    is_cation()
    is_anion()
    is_radical()
    is_zwitterion()
    is_ionic()

    # Charge, radical, phase, formula, and identity helpers
    get_charge_centers()
    get_radical_count()
    get_base_formula()
    get_identity()
```

## 🚀 Performance

- Lightweight helper methods operate on the validated component instance
- Charge and radical information is derived from the existing formula notation
- Identity strings are generated consistently from component fields
- No additional dependencies are required for the new Component methods

## ⚠️ Breaking Changes

None. This release adds helper methods to the existing `Component` model and
retains backward compatibility with the charge inference and validation
behavior introduced in v0.8.0.

## 📝 Notes

- Charge notation remains enclosed in curly braces: `{+}`, `{-}`, `{2+}`, etc.
- Radical notation uses `{*}`, with optional charge: `{*+}`, `{*-}`, `{*2+}`, etc.
- `get_charge_centers()` reports local charge values in formula order.
- `get_net_charge()` reports the component's total charge.
- A component can have internal charge centers even when its net charge is `0`.
- Explicit `charge` values must match the charge inferred from the formula.
